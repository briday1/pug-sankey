Pug Sankey

Complete offline reference for building, styling, editing, and exporting source-first Sankey diagrams.

Getting started

A Sankey diagram is a plain .pug file. Nodes are the vertical bars; flows are the ribbons between them. The value on each flow sets the ribbon thickness, and each node bar grows to match the total throughput passing through it. The smallest diagram is two nodes and one flow:

node
  .id source
  .label Source
node
  .id target
  .label Target
flow
  .from source
  .to target
  .value 10

This renders two bars, Source on the left and Target on the right, joined by a ribbon 10 units thick. Indentation defines ownership; use two spaces consistently. Blank lines and lines beginning with // are ignored. Save the Pug source to keep the diagram editable; PNG and SVG are export formats. Everything can be done entirely in the source editor, entirely on the canvas, or both.

Nodes

Every node starts with bare node; keep its fields dotted beneath the declaration. Nodes are laid out into columns automatically from the flow direction — a node with no incoming flows sits on the left, and each flow moves its target one column to the right.

node
  .id industry
  .label Industry
  .color #64748b
  .layer 1
  .offset (0, 24)
  .annotation
    .above
      | Largest single consumer
      | Updated for 2026
  .annotation
    .below
      | Includes construction
  • .id — unique identifier used as a flow endpoint. Required for any node a flow touches.
  • .label — text shown beside or on the bar.
  • .value — optional; sets the node's own value. A node's flows normally determine its total throughput, but a declared .value is authoritative (handy for a node with no flows yet) and must match the flow total when both are present, or the source is flagged as invalid.
  • .color — bar color; ribbons also blend from and to it (see Colors and blending).
  • .layer — stacking order when bars overlap; higher layers render in front.
  • .hidden — removes the bar and every touching flow from the render while keeping the source in place.
  • .offset (x, y) — manual nudge in pixels. Written automatically when you drag a bar on the canvas.
  • .annotation — free text attached to the node. Nest .above or .below for the starting position, then indent | text lines beneath it. Annotations may be dragged to write their own .offset.

Flows

Every flow explicitly identifies its source and target node by ID, plus a value. .value is required and must be a positive number — it determines the ribbon thickness. An optional .color pins the ribbon color and .label places text on the ribbon.

flow
  .from coal
  .to electricity
  .value 28
flow
  .from coal
  .to heat
  .value 8
flow
  .from renewables
  .to electricity
  .value 30
  .color #16a34a
  .label Wind and solar

Multiple flows out of one node render as a branch; multiple flows into one node render as a merge. Branching and merging are arbitrary — no separate keyword is needed. Node bar heights always follow throughput: a bar is exactly as tall as the sum of the flows entering or leaving it, so merges and splits stay visually balanced.

Colors and blending

Each node takes its own bar color with .color. Each flow may also take an explicit .color, which paints the whole ribbon in that single color.

Flows without an explicit color blend automatically between their endpoint colors: the ribbon starts at its source node color and finishes at its target node color. The canvas setting .blend N (0–100) controls how far the color travels across the ribbon — 0 keeps the source color until the very end, 100 shifts fully to the target color, and the default 60 eases most of the way across.

.background #ffffff
.blend 60

node
  .id renewables
  .label Renewables
  .color #22c55e
node
  .id electricity
  .label Electricity
  .color #2563eb
flow
  .from renewables
  .to electricity
  .value 30

Diagram settings and themes

Open Settings → Diagram settings for flow shape, background, color blending, and label/value controls. These are saved in Pug and used by the editor, CLI, SVG, and PNG exports. The editor's light/dark appearance is a separate setting.

.theme wiggly
.background #18181f
.blend 60

.theme smooth keeps the original continuous curves and is the default for existing files. wiggly adds broad waves, angular uses crisp diagonal turns, and terraced uses rounded transitions with level stretches. All retain solid ribbons, pointed endings, and the same quantity scale. Feedback loops retain their dedicated lanes, with angular turns in the Angular theme. Under an explicit #canvas, indent these fields by two spaces.

Three further styles are arc for raised arches, ripple for repeated shallow waves, and circuit for orthogonal runs with rounded elbows. These are flow-shape styles, not color palettes. The editor's Light/Dark toggle starts with your system preference and remembers your choice once toggled; there is no separate System option.

Also available: zigzag for alternating faceted bends, staircase for three crisp steps, sail for an early asymmetric crest, dip for rounded bowls, and s-bend for long entrances and a concentrated central turn. All twelve themes are selectable in Diagram settings.

Labels and values

Four canvas settings toggle text independently. Each accepts show or hide:

.node-labels show
.node-values show
.flow-labels show
.flow-values show
  • .node-labels — the text label on each node bar.
  • .node-values — the total throughput value shown with each node.
  • .flow-labels — the text labels placed on ribbons via .label (hidden by default).
  • .flow-values — the numeric value shown on each ribbon.

Node annotations (see Nodes) are separate from these settings and are always shown unless individually hidden.

Reusable styles

Use Settings → Diagram settings to show or hide totals and flow values, set colors, and adjust typography. The settings are saved in Pug: .node-values hide, .flow-values hide, .label-color #dce4e7, .node-value-color #8f9fa8, .flow-value-color #f2c879, .label-font-size 11, and .value-font-size 9. Clear a color field to return to automatic coloring. These settings also apply to SVG and PNG exports.

Reusable definitions are written directly at the source root, so the complete diagram stays in one Pug file:

@node source {
  color: #57534e;
}

@flow highlight {
  color: #dc2626;
  label: Featured;
}

@annotation note {
  color: #2563eb;
  font-style: italic;
}

Apply a reusable type by nesting .name inside a bare declaration — .source inside node, .highlight inside flow, and .note inside an annotation. Local fields beneath an item override its reusable type.

node
  .source
  .id coal
  .label Coal
flow
  .highlight
  .from coal
  .to electricity
  .value 28

Canvas editing

  • Click a node bar, ribbon, or label to select it and jump to its source line.
  • Drag a bar, ribbon label, or annotation to nudge it; the new position is written back to the source as an .offset.
  • The inspector edits node fields (label, color, layer, hidden, annotations) and flow fields (from, to, value, color, label) directly, keeping source and canvas in sync.
  • Clean Up snaps offsets to a tidy layout, removing small accidental drags while preserving deliberate placement.
  • The right-side Objects panel lists every node and flow; click an entry to select it on the canvas and in the source.
  • Undo/Redo and Ctrl+Z/Ctrl+Y cover canvas and direct source edits, including edits that temporarily cause a parse error.
  • Zoom affects preview only; Fit frames the diagram. Exports use diagram bounds.

Editor modes

The source panel is collapsible — Hide source folds it away for canvas-only work and remembers the preference. The single Pug editor holds both structure and reusable definitions. A theme toggle switches between light and dark. Vim mode is off by default and supports Normal, Insert, and Visual modes, a block cursor, movement/edit/yank/paste/marks, and Escape/Ctrl+[ to return to Normal mode; enable it in the editor or with --vim. The source editor syntax-highlights keywords, dotted fields, colors, numbers, offset tuples, and comments.

Export and CLI

Copy writes a high-DPI PNG to the clipboard. Save exports PNG or SVG, with resolution options for PNG.

pug-sankey diagram.pug            # render diagram.pug to diagram.png
pug-sankey diagram.pug -o out.png --scale 2
pug-sankey --demo 3               # open the GUI with demo 3
pug-sankey --gui diagram.pug      # open diagram.pug in the editor
pug-sankey --vim --gui diagram.pug

Direct rendering uses an installed Edge, Chrome, or Chromium browser in headless mode.
